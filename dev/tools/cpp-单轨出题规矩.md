/* 喵站 · C++ 单轨出题规矩（第十九轮）
 *
 * 为什么要有这一页：C++ 两门课 183 场考试正在改成「单轨」—— 一场卷只留一种形状。
 *   机器能改的 123 场由 dev/tools/cpp-exam-single-track.cjs 一次摊完；剩下 64 场要么缺编辑器题、
 *   要么有摊不开的写作题，必须人写题。这一页收的就是「人写题时照什么办」，派单只写号段，不再重抄口径。
 * 跑法：派单正文里写「先读 dev/tools/cpp-单轨出题规矩.md」。
 */

一、交付物只有一份 JSON（别的都不许动）

  1. 你要写的文件：`dev/tools/cpp/authored/<cid>.json`，一场一份（cid 就是 c01 / m137 这种课号）。
  2. 一律禁改：`dev/frontend/assets/data/**`（考卷产物由改造器独占写出）、`dev/tools/cpp-exam-check.cjs`（闸）、
     `dev/tools/cpp-exam-single-track.cjs`（改造器）、`dev/tools/cpp/exam-mode.json`（分配表）、
     `frontend/assets/js/**`、`frontend/assets/css/**`、`任务书.md`。
     **觉得闸判错了就把现象写进回报，不许自己放松闸。**
  3. 不许跑 `--write`。落盘由主控做，你只 `--verify`。
  4. 不许通读考卷产物、不许读判分器源码。底稿命令给什么就看什么。

二、三条命令（照着用，别自己发明）

  1. 拿底稿：`node dev/tools/cpp-exam-seed.cjs <cid>`　——　打出这一课的【任务】逐条编号、正文里教过
     的写法（小标题＋全部演示代码）、这一场现有的每道题（含判分正则与三档自测）、以及闸判它缺什么。
     多场可以一次传：`node dev/tools/cpp-exam-seed.cjs c16 c18`。
  2. 验自己的号段：
     `node dev/tools/cpp-exam-single-track.cjs --authored dev/tools/cpp/authored --verify --only <你的 cid，逗号隔开>`
     最后一行要看到 `[verify] 闸绿 ✔ 可以 --write` 且 `错误 0`。红就按它点的名改你的 JSON，再来一遍。
  3. 号段互斥：`--only` 只写你被派到的那些 cid。别人的场红着不归你，别去查。

三、单轨的硬形制（闸逐条判，一条不过就红）

  代码卷 `mode: "code"`
    · 一场卷从头到尾只有 code 题（一题一枚小编辑器），3–6 道；
    · 每道 code 题必须给 `acceptRegex`（只写字面 `accept` 会把等价写法判错，闸直接拦）；
    · 源稿每条【任务】都得有 code 题的 coversTask 对着它 —— 改造时会把非 code 题全删掉，
      任务只被 choice/output 盖着的话，必须为那条任务补一道 code 题；
    · 任务题合计 ≥50 分。
  笔试卷 `mode: "quiz"`
    · 一道 code 题都不许有，6–10 题；
    · ≥2 道 choice、≥1 道 output、≥1 道 blank 或 match（他要的「词语填空、勾线题这种」）；
    · 源稿每条【任务】都要有题盖住：删掉那道编辑器题之前，先看卷里是不是别的题已经在验同一件事
      （例如那道 output 题问的就是「这段写全之后打什么」）—— 是的话用 `retag` 把对账挪过去，
      别再新写一题凑数；
    · 任务题合计 ≥50 分。
  勾线题（match）另有两条：至少 3 对；不许「左第 i 项连右第 i 项」整卷自对（把右边顺序打乱）。

四、JSON 形状（两个样板照抄）

  样板一（补代码题）：`dev/tools/cpp/authored/c01.json`
  样板二（retag 挪对账 + 删写作题）：`dev/tools/cpp/authored/c29.json`

  {
    "cid": "c16",
    "note": "为什么要人工题（一句话，主控看）",
    "add": [
      { "temp": "a1",
        "q": { "type": "code", "score": 25, "coversTask": 2,
               "stem": "题面（读者看到的，人话）",
               "acceptRegex": ["正则1", "正则2"],
               "sample": "参考写法一行",
               "why": "复盘里给读者看的那句解释" },
        "selftest": { "ref": "该拿满分的参考解",
                      "wrong": "必定判错的解",
                      "loose": "空格、大小写、换行写歪也该过的解" } }
    ],
    "drop": ["q4"],
    "retag": [{ "id": "q8", "coversTask": 2 }]
  }

  1. `temp` 是临时题号（a1、a2…），**别写 id**：改造器最后统一重排成 q1…qN，三档自测的键会跟着换。
  2. `q.score` 必须给：不给就按最小权重挤进去，一道大题只摊到 5 分。
  3. 每道 add 都要 `selftest.ref / wrong / loose` 三条齐全 —— ref 判不满 100、wrong 竟然过了线、
     loose 被当成错解，闸都会红并点名。
  4. 新写的 code 题也要 `sample`：判错后复盘里给读者看的是这行参考写法，不是裸正则。
  5. 笔试卷的 add 不许是 code 题、代码卷的 add 必须是 code 题 —— 形状不对改造时会直接删掉，白写。

五、题面口径（正文那套规矩在这里同样成立）

  1. 只用底稿〔正文里教过的东西〕出现过的写法。没教过的构造出现在题干或参考解里，构造首现闸会红。
  2. 读者可见字段（task/hint/stem/options/steps/left/right/why）：不许有梗、不许句尾「喵」、
     不许出现反引号、不许「第 N 课」往后指（N 大于本课号就是前向引用）。代码名裸写或用「」。
  3. `acceptRegex` 的松紧：关键字在就判对，空格、缩进、大小写、变量名一概不计较；
     但也不许松到「随便打个 x 也算对」。多条正则默认是「条条都得在」；只要求命中其中一条时写
     `"matchAny": true`。反斜杠在 JSON 里要写两条（`"\\s+"`）。
  4. 题目是「这一课学过能不能动手做」，不是文字游戏；一道题只问一件事。
  5. 分值由你定（一题 15–30 分之间），改造器只负责把总分摊平回正好 100。

六、落盘纪律

  1. 一场一份，写完立刻落盘，别攒着一起交（断线就全没了）。
  2. 第一份文件必须在前 3 次工具调用以内写出来。
  3. 已经存在的 `<cid>.json` 是别人的成果或已验过的样板：**只许追加、不许整份重写**。
  4. 回报格式：每场一行 —— `<cid> · 加了几道什么型 · retag/drop 用了没 · 闸绿还是闸红`，
     外加你觉得不对劲的地方（闸判错、任务本身没法考之类），别替主控做决定。

七、笔试卷缺题的三种形状（各自怎么办）

  B 类「多正则写作题降级不了」
    闸报「qN 是 X 条正则的写作题，任务 M 只有它盖着」。先别急着写新题：
    这一场里通常已经有一道 output / choice 题在做同一件事（例如它问的就是「第三道门加好之后打什么」）。
    有的话就 `retag` 把任务对账挪给那道题，再 `drop` 掉 code 题 —— 样板 `dev/tools/cpp/authored/c29.json`。
    确实没有题在验这条任务，才新写一道 blank / match / output 把它盖住，然后 drop。

  C 类「删掉代码题只剩 5 题，不足 6 题」
    新写 1–2 道非 code 题补到 6 题以上。优先写勾线（match）或填空（blank）—— 这两种形状本来就稀罕。
    新题最好顺手也盖一条任务，摊分后任务题 ≥50 分这条更稳。

  D 类「改完一道填空/勾线都没有」
    这一场的题已经单轨了，只差一种形状：新写一道 match 或 blank 即可。
    注意卷里已有的题号是改造重排过的（q1…qN），要 drop 就按底稿打出来的当前题号写。

八、勾线题（match）怎么写

  { "type": "match", "score": 18, "coversTask": 1,
    "stem": "把左边的写法和它真正的效果连起来（右边顺序是打乱的）。",
    "left":  ["中括号里只写 [base]", "中括号里写 [base, tag]", …],      // 3–5 项
    "right": ["lambda 里的 base 仍是定义那一刻抄下的旧值", "只抄 base 一个名字", …],  // 与 left 同数或更多
    "answer": { "中括号里只写 [base]": "只抄 base 一个名字", … },        // 左边文字 → 右边文字
    "why": "一句人话讲清这条规律" }

  1. 至少 3 对，少于 3 对是送分，闸直接拦。
  2. **右边顺序必须打乱**：不许「左第 i 项正好连右第 i 项」，那样不用想就连完了，闸也拦。
  3. 三档自测这么给：`ref` 用文字连全对；`wrong` 全部张冠李戴（一对都别对）；
     `loose` 可以改用编号连（`{"0": 1, "1": 3, …}`，左编号→右编号）—— 判分器两种都认，
     这样 loose 就在验「读者用别的方式答也该得分」。样板 `dev/tools/cpp/authored/c57.json`。
