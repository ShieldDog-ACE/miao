 * 135 场笔试卷摊不出来（选择题里没有可判的代码写法），必须有人按源稿【任务】重写条件。
 * 这一页收的就是「人写题时照什么办」，派单只写号段，不再重抄口径。
 * 跑法：派单正文里写「先读 dev/tools/cpp-单编辑器出题规矩.md」。

一、交付物只有一份 JSON（别的都不许动）

  1. 你要写的文件：`dev/tools/cpp/ide/<cid>.json`，一场一份（cid 就是 c02 / m137 这种课号）。
  2. 一律禁改：`dev/frontend/assets/data/**`（考卷产物由改造器独占写出）、
     `dev/tools/cpp-exam-check.cjs`（闸）、`dev/tools/cpp-exam-ide.cjs`（改造器）、
     `dev/tools/cpp-exam-print.cjs`（打印器）、`frontend/assets/js/**`、`frontend/assets/css/**`、
     `dev/任务书.md`、`SPEC.md`。**觉得闸判错了就把现象写进回报，不许自己放松闸。**
  3. 不许跑 `--write`。落盘由主控做，你只 `--verify`。
  4. 不许通读考卷产物、不许读判分器源码。底稿命令给什么就看什么。

二、三条命令（照着用，别自己发明）

  1. 拿底稿：`node dev/tools/cpp-exam-seed.cjs --ide <cid>`　——　打出这一课的【任务】逐条编号、
     正文里教过的写法（小标题＋全部演示代码）、这一场现有的每道题（题干 / 选项 / 为什么），
     以及这一场现在是什么形状。多场可以一次传：`… --ide c02 c03`。
  2. 验自己的号段：
     `node dev/tools/cpp-exam-ide.cjs --authored dev/tools/cpp/ide --verify --only <你的 cid，逗号隔开>`
     报告里你每一场都必须是 `✔`，最后 `[cpp-exam-check] … 错误 0`。红就按它点的名改你的 JSON，再来一遍。
  3. 号段互斥：`--only` 只写你被派到的那些 cid。别人的场红着不归你，别去查。

三、单编辑器的硬形制（闸逐条判，一条不过就红）

  · 一场卷 = 一块编辑器：整份文件就是读者写的那一份程序，条件全写在文件顶部的 // 注释里；
  · 条件 3–6 条，每条都必须是 `type:"code"`（选择型 / 勾线型在这块编辑器里判不了，闸直接红）；
  · 每条必须给 `acceptRegex`（判分只有「在代码里找关键写法」这一条路）**和** `sample`
    （判错了复盘要给读者看参考写法，不许甩裸正则）；
  · 各条 score 相加正好 100；带 coversTask 的条件合计 ≥50；源稿每条【任务】都要有条件盖住，
    编号不许越界（这一课只有 2 条任务就别写 coversTask:3 —— 上一轮被这条抓到过 4 场虚号）；
  · `starter`（编辑器预置的骨架）单独交卷必须判不过线：骨架不许替读者做完任何一条条件。
    拿不准就留空字符串 —— 空的一定过这条；
  · 三档自测 `refs / wrongs / loose` 都是**整份代码的字符串**（不是按题号给的答案表）：
    refs 判 100、wrongs 判 <60、loose 判 ≥60；loose 与 refs 一字不差会被当成没自测，直接红。

四、JSON 形状（样板就一份：`dev/tools/cpp/ide/c02.json`，照它的字段写）

  {
    "cid": "c02",
    "note": "为什么这么出（主控看，一句话）",
    "starter": "",
    "checks": [
      { "stem": "条件一句话（读者在题面注释里看到的就这句）",
        "acceptRegex": ["正则1", "正则2"],
        "sample": "这一条的参考写法",
        "why": "复盘里给读者看的那句解释",
        "coversTask": 1, "score": 20,
        "acceptOn": "code" }
    ],
    "notes": [ "旧题里的知识点原话，留在题面注释里给读者看，不判分" ],
    "selftest": { "refs": ["整份满分代码"], "wrongs": ["空串也算一档", "整份典型错代码"], "loose": ["换空格换变量名也要过"] }
  }

  1. 别写 `id`：改造器统一排成 q1…qN。
  2. `score` 必须给（一条 15–30 之间），不给就按最小权重挤进去。
  3. 多条 `acceptRegex` 默认是「条条都得在」；只要求命中其中一条时写 `"matchAny": true`。
     反斜杠在 JSON 里要写两条（`"\\s+"`）。
  4. `acceptOn` 两档：
     · `"code"`（缺省）：在**剥掉注释之后**的代码里找 —— 把条件原文抄进注释不该得分；
     · `"buffer"`：在读者自己写的那一段里找，**注释也算**。只有两类条件配得上它：
       ① 判的不是程序本体而是 shell 命令（「写出编译命令」）；
       ② 判的是「你在注释里记下了观察到什么」（「把报错第一行抄下来」）。
       题面那几行注释永远不参与匹配，所以别指望读者靠留着题面白拿分。
  5. `notes` 是这一场退役的笔试知识点的**原话**（从底稿里那些 `为什么：` 抄并压缩），最多 5 条，
     每条一句完整的话。它们进题面注释、不判分，是这次改造里旧题唯一的去处。

五、哪些任务没法变成代码条件（照这一节的办法办，别硬出题）

  · 「读一读报错第一行说了什么 / 你观察到什么」：写成一对 —— 一条 `code` 条件要求读者把那行
    不合法的代码真写出来（例如 `char grade = "A";`），再加一条 `buffer` 条件要求他旁边跟一行
    至少四个字的注释。正则只能验「他写了注释」，验不了注释内容 —— 这是这块编辑器判不动的部分，
    在 `why` 里照实说一句，别假装它被严格判了。
  · 「预测输出再验证」：`code` 条件要求那条打印语句真写出来（占位坑、参数个数都对），
    预测这件事本身收进 `notes`，不判分。
  · 纯概念题（「int 盒能装哪个值」「auto 猜完还能不能改」）：只能进 `notes`。
    一场卷里如果这种题占了大头，任务条件凑不到 50 分 —— 别为了过闸编一条假代码条件，
    把卡住的现象写进回报，主控来处理。

六、题面口径（正文那套规矩在这里同样成立）

  1. 只用底稿〔正文里教过的东西〕出现过的写法。没教过的构造出现在 `stem` / `sample` / `notes` /
     `starter` / `why` 里，构造首现闸就红（这几栏现在全算读者可见字段）。
  2. 不许有梗、不许句尾「喵」、**不许出现反引号**（会把分部文件的字符串切坏）、
     不许「第 N 课」往后指（N 大于本课号就是前向引用）。代码名裸写或用「」。
  3. `acceptRegex` 的松紧：关键写法在就判对，空格、缩进、大小写、变量名一概不计较；
     但也不许松到「随便打个 x 也算对」。
  4. 条件要写成「这一课学过能不能动手做」的祈使句（写一行… / 把…补进来 / 用一条 println…），
     一条只问一件事，别把两件事塞进一条正则。

七、落盘纪律

  1. 一场一份，写完立刻落盘，别攒着一起交（断线就全没了）。
  2. 第一份文件必须在前 3 次工具调用以内写出来。
  3. 已经存在的 `<cid>.json` 是别人的成果或已验过的样板：**只许追加、不许整份重写**。
  4. 回报格式：每场一行 —— `<cid> · 几条条件 · 哪几条是 buffer · notes 收了几条 · ✔ 还是红（红就抄闸的原话）`，
     外加你觉得不对劲的地方（任务本身没法用代码判、闸判错之类），别替主控做决定。
